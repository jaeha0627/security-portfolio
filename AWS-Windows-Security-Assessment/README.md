# AWS Windows WAS Security Assessment

SK쉴더스 루키즈 35기 · 2026.11 · 5인 팀 프로젝트

## 프로젝트 개요
AWS 기반 Web/WAS/RDS 교육용 환경에서 KISA 주요정보통신기반시설 기술적 취약점 분석·평가 기준에 따라 보안 상태를 점검했습니다. 본인 담당은 Windows Server 2019 WAS 진단 및 결과 문서화였습니다.

## 팀 환경
| 구성 | 기술 |
|---|---|
| 인프라 | AWS VPC, EC2, ALB/NLB |
| Web | Linux, Apache |
| WAS | Windows Server 2019, Tomcat |
| DB | MySQL RDS |

## 본인 수행 범위
- Windows 진단 기준 W-01~W-53 범위에서 계정, 서비스, 보안 설정 및 패치 상태 확인
- PowerShell 및 Windows 관리 도구를 활용한 설정값 조회와 증빙 기록
- 취약 판단 근거와 개선 권고를 구분해 보고서 작성
- 팀 보고서 양식 통일, 자료 취합 및 발표 준비 협업

W-01~W-53은 기준 항목 범위를 뜻하며 발견 건수 또는 전 항목 완료 건수를 의미하지 않습니다.

## 대표 진단 결과
| 항목 | 초기 판단 | 근거 및 개선 방향 |
|---|---|---|
| W-38 주기적 보안 패치 및 벤더 권고사항 적용 | 취약 | 점검 당시 OS 빌드 및 업데이트 설치 내역을 보고서 기준과 대조. 적용 대상 업데이트 확인, 영향 검토, 적용 후 재검증 권고 |
| W-39 백신 프로그램 업데이트 | 양호 | 백신 업데이트 상태 점검 |
| W-40 정책에 따른 시스템 로깅 설정 | 취약 | 감사 정책 및 중요 이벤트 기록 설정 확인 필요 |
| W-41 NTP 및 시각 동기화 설정 | 양호 | 시각 동기화 상태 점검 |
| W-42 이벤트 로그 관리 설정 | 취약(잠정) | 중앙 수집 및 보존 여부 추가 확인 필요 |
| W-43 이벤트 로그 파일 접근 통제 설정 | 양호 | 이벤트 로그 접근 통제 설정 점검 |

## 점검 방법
1. KISA 기준의 점검 목적 및 판단 기준 확인
2. PowerShell과 관리 화면에서 실제 설정값 조회
3. 기준과 조회값을 대조하여 양호·취약 판단
4. 증빙 및 개선 권고를 보고서에 기록

패치 관리와 로그 관리 보고서는 2026년 11월 12일 초기 진단 기준입니다. 실제 패치 설치, 재부팅 및 해당 설정 변경을 수행했다고 주장하지 않습니다.

## 참고 기준
KISA, 2026 주요정보통신기반시설 기술적 취약점 분석·평가 방법 상세가이드, Windows 서버 항목.

## 공개 범위
교육용 환경에서 수행한 개인 담당 업무를 요약했습니다. 원본 보고서, IP 주소, 계정 정보, AWS 식별자 및 팀 내부 자료는 공개하지 않습니다.
